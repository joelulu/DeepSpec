# Flexible looped DFlash experiments

## Run

Edit `scripts/loop/settings.sh`. The default source is the existing
`qwen3_4b_target_cache_130w_20260713_041400` cache. No subset directory,
index file, shard copy or symlink is generated by the new training entrypoint.

```bash
bash smoke_dflash_flex.sh        # Two optimizer steps; isolated smoke output
bash run_dflash_experiments.sh   # Five groups, sequentially, all eight GPUs
bash eval_temp.sh               # AR and every trained loop depth in the five groups
```

The queue is: 5x1 raw, 15x1 raw, 1x5 raw, 5x3 raw, 5x3 rmsnorm.
All use final-exit loss, three epochs and the same samples/anchors.
`run_dflash_experiments.sh` explicitly selects GPUs 0-7; `MATRIX_GPUS` overrides
that list. It stops on a failed job. Completed groups are recognized on rerun.
By default only the final model is saved, without optimizer/RNG `.pt` files;
interrupted runs therefore restart from scratch. Legacy checkpoints with
training state can still resume with identical settings.

Individual training takes exactly two integers:

```bash
bash train_dflash_loop.sh 15 1
LOOP_TRANSFER=rmsnorm bash train_dflash_loop.sh 5 3
```

The old `5l`, `15l`, `loop5x3` aliases map to these new defaults and NEW run
names. They do not resume the earlier two-epoch pilot. Earlier checkpoints
remain evaluable, e.g.:

```bash
bash eval_temp.sh runs/dflash_loop_3pct/deepspec/dflash_4b_5l_3pct_seed42/step_latest
bash eval_dflash_flex_prefix.sh runs/dflash_flex/deepspec/dflash_L5_R3_p3_e3_rmsnorm_final_seed42/step_latest
```

## Data and schedule

`DATA_PERCENT` accepts decimal percentages in (0,100]. Reserve
`HOLDOUT_SAMPLES=32` fixed samples before sampling; the percentage applies to
the remaining training pool. The holdout is identical across models and
percentages for the same cache and seed, and never used for training.
Selection is fixed across epochs, without replacement, sorted by original
sample ID, and identical on every rank. Equal percentage + seed gives the same
samples; subsets at different percentages are not guaranteed to be nested.
Set `HOLDOUT_SAMPLES=0` to disable cache validation. At 100%, all eligible
training samples are used. Too-small selections fail before CUDA training.

With 1,339,767 source samples, the default holds out 32 and selects 40,192
training samples. Global batch 256 gives 157 steps per epoch, 471 steps total,
and validates at 157/314/471, saving only the final model at 471. Eight GPUs x
local batch 4 implies accumulation 8.
The last incomplete global batch is dropped each epoch as in the original
trainer; shuffling changes its membership between epochs.

`run_identity.json` protects resume against changed source metadata, sample
selection, model settings, LR, epochs, batch size or GPU count. Use another
`RUN_ROOT` for an intentional new experiment. The source cache should remain
immutable during a run. The fingerprint includes the cache path/manifest and
selected sample IDs; it does not hash all shard contents.

## Structure and loss

`LOOP_TRANSFER=raw` preserves the legacy recurrent state: raw stack output is
passed to the next loop, while norm is used only for exit prediction.
`LOOP_TRANSFER=rmsnorm` feeds that same normalized exit state into the next
loop, without applying a second normalization. Both share the physical stack,
its projected target context K/V, and the output norm/head across loops.
Block Q/K/V are recomputed each iteration; no predicted tokens or probabilities
are fed back. Existing checkpoints default to raw when the new field is absent.
The original Qwen3 pre-normalized decoder structure and initialization remain.
Sandwich norm and a learned exit gate are deliberately reserved for a later
experiment, after results justify them.

`LOOP_LOSS=final|uniform|late`: final is [0,...,0,1], uniform equal positive
weights, late weights proportional to loop index. Weights are normalized.
The last-mode choice is a simple configurable ablation, not a reproduction of
Ouro's learned exit distribution. For zero-weight exits, detach only the
monitoring head input; the recurrent backbone remains connected for final-exit
backpropagation. Pure CE training skips unnecessary teacher-logit reconstruction
and probability-overlap diagnostics; greedy acceptance is measured by eval.

## Logs and evaluation

Console logs: `RUN_ROOT/logs/<experiment>.log`.
TensorBoard: `RUN_ROOT/tensorboard/deepspec/<experiment>`.

- `train/objective`: actual weighted objective, globally averaged.
- `train/loopN/ce_loss`: CE with the original within-block position decay.
- `train/loopN/ce_unweighted`: token CE without loop or position weighting.
- `train/loopN/weighted_contribution`, `/weight`: contribution to the objective.
- `state/loopN/hidden_rms`, `/relative_update`: raw stack-output RMS and change
  relative to loop input. Sampled on the first microbatch every 20 optimizer
  steps, excluding padding blocks. These state statistics are rank-averaged
  diagnostics, not proof of convergence.
- `train/lr`, `train/grad_norm`: LR and global gradient norm before clipping.
- `validation/loopN/ce_unweighted`: token-weighted CE on the fixed holdout,
  same deterministic anchors per sample; evaluated each epoch and at the final save. This small
  cache check measures teacher-forced block loss, not generation throughput.

`config/loop/dflash_flex_qwen3_4b.py` sets `logging.save_only_final=True` and
`logging.save_training_state=False`. The final `step_<N>` model directory is
linked from `step_latest`, so evaluation commands are unchanged. A small
`checkpoint_meta.json` records completion for queue reruns; it contains no
optimizer tensors or RNG state. Existing checkpoint directories are not deleted.
Other training configs retain their original saving/resume behavior by default.

`eval_temp.sh` accepts zero or more checkpoint paths, reads maximum loops from
config, runs all valid depths, and uses a fresh output directory. Default:
GSM8K, 16 samples, 256 new tokens, greedy, one warmup sample. `EVAL_GPU=0` selects
the timing GPU. Run on an idle GPU. `EVAL_REPEATS=3 MAX_SAMPLES=128` gives
separate repeated comparisons; each repetition has its own AR baseline/CSV.
To add tasks, edit TASKS or use `TASKS=gsm8k,mbpp,alpaca`.

The CSV distinguishes:

- `serial_decode_tps`: tokens generated after the first prefill-produced token,
  divided by synchronized decode wall time.
- `serial_generation_tps`: all generated tokens divided by generation wall time,
  including prefill. This excludes model loading, tokenization and server queueing.
- `draft_ms`, `verify_ms`: cumulative stage times across samples, not per-round
  means; `round_wall_ms` is the average full decode-round wall time.
- acceptance length includes the verifier bonus token under the existing metric;
  same-prefix `accepted_draft_tokens` excludes that bonus.

Same-prefix diagnostics now support arbitrary N, preserve one deepest-loop
rollout, and report all 1..N exits. Oracle remains offline, uses future
information, excludes gate overhead, and does not establish real speedup.

## 15L audit and limits

Confirmed in source and tiny CPU models:
- 5L/15L use independent randomly initialized draft decoder layers; target
  embedding/LM head are copied and frozen. No target decoder layers are extracted.
- All 15 decoder layers, context projection and their attention projections/MLP output projections
  receive finite nonzero gradients from final-exit supervision.
- Checkpoints store actual depth/loops/normalization; incompatible training
  resumes now fail rather than silently replacing the requested architecture.
- Cached and full-context draft computation agree; greedy speculative output
  agrees with target AR with and without boundary normalization in tested cases.
- The sample-shuffle seed now follows the configured experiment seed instead of
  silently retaining the sampler's default 42.

No confirmed implementation bug explains the reported 15L acceptance deficit.
Equal epochs answer performance under the same data exposure, not each depth's
best achievable performance. If 15L validation CE remains high, revisit LR or
budget; if CE improves without acceptance, investigate generation mismatch.

Verification here is CPU-only with tiny Qwen3 models and synthetic cache data.
The real target cache/GPU environment is unavailable; the eight-GPU FSDP and
BF16/flex-attention path must be checked using `smoke_dflash_flex.sh`.
Training prints git provenance; it does not run `git commit` or `git push`.

References: [Ouro paper](https://arxiv.org/abs/2510.25741),
[official inference model](https://huggingface.co/ByteDance/Ouro-1.4B/blob/main/modeling_ouro.py).

For an inference-only comparison on a frozen looped checkpoint, see
